# Risk Assessment - Legacy Inventory & Order Management System (`risk_assessment.md`)

Prioritized technical, security, and operational risks identified across the `legacy_code_interpreter` codebase, ranked by severity and potential business impact.

| Risk | Severity | Notes |
| :--- | :--- | :--- |
| **SQL Injection Vulnerabilities** | **High** | Raw user inputs (`$_POST['order_id']`, `$item['sku']`) are directly concatenated into SQL queries without sanitization or prepared statements across core controllers (`controllers/process_order.php`). |
| **Broken Authentication & Privilege Escalation** | **High** | Passwords are hashed using MD5 with a static salt and loose comparison (`==`), while user roles are read directly from an unsigned browser cookie (`$_COOKIE['user_role']` in `includes/auth_session.php`). \vert{} \vert{} **Deprecated `mysql_*` API Usage** \vert{} **High** \vert{} Relies on procedural `mysql_query()` and `mysql_fetch_assoc()` extensions removed in PHP 7.0+, blocking runtime upgrades and exposing the server to unpatched PHP 5.6 vulnerabilities. \vert{} \vert{} **Hardcoded Credentials & Secrets** \vert{} **High** \vert{} Database passwords, SMTP credentials, and third-party API keys are hardcoded in plaintext across 19 source and configuration files (`config.php`, controllers) committed to version control. \vert{} \vert{} **Non-Transactional Inventory Deductions** \vert{} **High** \vert{} Multi-item order processing (`process_order.php`) deducts stock sequentially without database transactions (`BEGIN`/`ROLLBACK`), causing partial inventory corruption when mid-order items fail stock checks. \vert{} \vert{} **Inventory Lost-Update Race Conditions** \vert{} **Medium** \vert{} Warehouse stock synchronization (`cron/sync_stock.php`) uses a non-atomic Read-Modify-Write pattern in PHP memory, overwriting concurrent customer order deductions. \vert{} \vert{} **Zero Automated Test Coverage** \vert{} **Medium** \vert{} Critical checkout, pricing, and reconciliation modules have no unit or integration tests, making every bug fix or refactoring effort prone to silent regressions. \vert{} \vert{} **Tight Coupling & Mixed Paradigms** \vert{} **Medium** \vert{} SQL queries, business logic, global variables (`$DB_CONN`), and HTML/PDF rendering are interleaved inside 2,300+ line procedural scripts, preventing isolated component testing. |
| **Floating-Point Currency Rounding Drift** | **Medium** | Tiered discount and tax calculations (`libs/pricing_rules.php`) use native binary `float` arithmetic rather than integer cents or `BCMath`, causing cent-level invoice discrepancies. |
| **Lack of Structured Error Logging** | **Low** | Failures terminate abruptly via `die()` or fail silently without structured application logs, stack traces, or correlation IDs, slowing down production incident debugging. |
